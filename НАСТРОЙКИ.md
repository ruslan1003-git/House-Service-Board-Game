# Настройки игры

Все основные игровые параметры находятся в `game-config.js`. Этот файл подключён к обычной игре (`index.html`) и dev-версии (`dev.html`), поэтому одна настройка действует в обеих версиях.

## Как менять

1. Сделайте копию `game-config.js` перед крупными правками.
2. Откройте файл в редакторе текста (например, Блокнот или VS Code).
3. Меняйте значения справа от двоеточия, сохраняя кавычки, запятые и скобки. Для текста оставляйте кавычки; числа записывайте без кавычек.
4. Сохраните файл и перезагрузите игру. При запуске из папки откройте `index.html` заново или обновите страницу.
5. Чтобы увидеть изменения правил в уже сохраненной партии, начните новую игру: сохранение хранит часть параметров сотрудников и дома.

Не переименовывайте ключи вроде `startingCapital`, `salary`, `labor` и `materialCost`: игра ищет настройки по этим именам.

## Что где находится

- `companyNameDefaults` — случайные названия УК, если поле имени пустое.
- `seasons` — названия сезонов; порядок задаёт календарь игры. `seasonIcons` — значки в том же порядке.
- `houses` — дома: название, адрес, площадь и возраст в годах. Возраст старше трёх лет увеличивает число карт на каждом сезонном осмотре на одну за каждые полные три года после первых трёх.
- `roles` — базовые данные ролей: название, категория работ, зарплата, продуктивность, значок и описание.
- `employees` — перечень конкретных соискателей. Формат записи: должность, ФИО, продуктивность, ожидаемая зарплата, необязательная юридическая сила и бонус профиля. Исполнители в пуле сейчас имеют варианты продуктивности −1/0/+1 от базовой; рынок выбирает из этого списка без повторов, а уже нанятые профили из него исключаются.
- `requests` — колода заявок. Для каждой карты можно менять название, категорию, описание, трудозатраты, материалы, доход платной заявки, компенсацию ущерба и значок. `type` задаёт тип: `ordinary`, `emergency`, `emergencyDamage` или `paid`; платным заявкам также нужны `payout`, аварийным с ущербом — `damageCompensation`.
- `houseProblems` — проблемы и их износ. В `tasks` заданы категории/трудозатраты последствий и материалы; `seasonal` ограничивает заявку сезоном по индексу (лето 0, осень 1, зима 2, весна 3). `materialOnly` и `materialCost` используются для проблем, где нужны только материалы. Цена материалов при ремонте проблемы не может быть нулевой; минимальная сумма задаётся в `rules.problemMinimumMaterialCost`.
- `problemCardCounts` — число копий каждой проблемы в колоде осмотра.
- `problemConsequences` — короткие описания последствий для карточки дома.
- `oss` — настройки ОСС: модификаторы специалистов, влияние репутации на изменение тарифа, порог износа капремонта и бонус репутации при отказе от изменения тарифа. Капремонт: результат `S / 5 × d6 + модификаторы специалистов + число проблем категории`; порог `S / 2 + 1`. Изменение тарифа на X проводится отдельно для каждого дома в годовом отчёте (X может быть отрицательным): результат `S / 5 × d6 + модификаторы специалистов + репутация`; порог `S / 2 + отменённые заявки дома × 2 + X`. Тариф не может быть ниже нуля.
- ОСС «Новый дом» проводится один раз за ход с рынка недвижимости. Результат: `S выбранного дома / 5 × d6 + репутация + модификаторы специалистов`; порог: `S выбранного дома / 2 + все отменённые заявки игрока`.
- `economy` — начальные условия, тариф, содержание, порог банкротства, диапазон собираемости, количество обычных заявок на дом за сезон и надбавка подрядчика. Цена подрядчика для обычной заявки считается как зарплата роли по её категории + материалы + надбавка. Для ремонта проблемы стоимость работ дополнительно умножается на `problemRepairLaborCostMultiplier`.
- `rules` — лимиты рынка/найма, коэффициенты зарплат и переработки, осмотр, гарантийные суды, юристы и штрафы репутации. Параметры гарантии: `warrantyAgeYears`, `warrantyCourtFee`, `warrantySuccessChanceByLegalStrength`, `inspectionCardsPerThreeHouseYears`. Для гарантийного суда нужен штатный юрист; успешное дело устраняет покрытые проблемы и переводит связанные компенсации на застройщика. Капремонт по ОСС создаёт трёхлетнюю гарантию категории. Аварийный дом определяется по износу категории (`unsafeWearThresholdPercent`) либо общему числу карт проблем (`unsafeProblemCardThreshold`). Срок на устранение обоих условий задаёт `unsafeHouseGraceSeasons` в полных сезонах; устранение всех условий сбрасывает срок. Игрок также может признать дом аварийным раньше кнопкой в карточке дома.

## Примеры

Изменить тариф с 10 на 12 рублей за квадратный метр:

```js
tariffPerSquareMeter: 12,
```

Поменять зарплату сантехника:

```js
plumber: { name: "Сантехник", category: "Сантехника", salary: 22, productivity: 3, icon: "🔧", kind: "executor" },
```

Увеличить материалы для протекающего крана в записи этой заявки:

```js
materialCost: 8,
```

Юридическая сила юриста 1/2/3 задаёт зарплату 15/20/25 ₽, лимит взыскания из `lawyerDebtLimitByStrength` и диапазон снижения из `lawyerReductionRangeByStrength`; порядок массивов — сначала сила 1, затем 2 и 3.

## Важные ограничения формата

- Категории ролей должны совпадать с категориями заявок и задач проблем: `Сантехника`, `Электрика`, `Уборка`, `Общестрой`.
- Роли сотрудников используют ключи `plumber`, `electrician`, `janitor`, `handyman`, `lawyer`, `hr`, `accountant`, `engineer`. Не меняйте ключи, если не меняете логику игры.
- Для проблемы `tasks` — список её работ. Работы исполнителей требуют материалы, если у задачи задан `materialCost`; общее количество труда складывается по категориям.
- После ручной правки проверьте, что в консоли браузера нет ошибок. Ошибка синтаксиса в конфиге не даст странице запуститься.


## Уникальные бонусы специалистов

- HR: переброс рынка один раз за ход; расширенный рынок (+2 специалиста и +2 исполнителя); без бонуса.
- Инженер: минус 2 трудозатраты при самостоятельном решении проблем; скидка 30% на материалы для проблем; без бонуса.
- Бухгалтер: +10 п.п. собираемости (до 100%); скидка 20% на базовое обслуживание; без бонуса.

У бонусных профилей зарплата 20 ₽, у профиля без бонуса — 15 ₽.

Уникальные бонусы сотрудников указываются в `employees` через `bonus` и `bonusDescription`. Если в штате несколько сотрудников с одинаковым бонусом, числовой эффект суммируется; процентные скидки ограничены 100%, собираемость — 100%. Бонус переброса HR остаётся один раз на компанию за ход.
